# CSS and HTML support

This page lists what `htmltopdf` renders, what it approximates and what it
ignores. It is updated by every change that alters CSS or HTML support.

Anything not listed as supported is dropped and reported as a warning in
`Result.Warnings` (`unsupported-property`, `invalid-value`, `unsupported-at-rule`,
`unsupported-selector`, `unsupported-element`); the render never fails because of it.

Status values: **supported**, **approximated** (rendered differently from a
browser, with the difference stated), **ignored** (dropped with a warning),
**never** (not planned).

Output PDFs are not tagged: they have no structure tree and do not conform to PDF/UA
(Chrome's are tagged); text remains extractable through ToUnicode.

## Syntax, cascade and selectors

| Feature | Status | Notes |
|---|---|---|
| Origins | supported | UA sheet, document (`<style>` and `style=""`), then ExtraCSS, which wins over every document declaration, `!important` and `style=""` included. Inside the document, `!important` beats normal, and the style attribute beats the selectors. |
| `inherit`, `initial`, `unset` | supported | `all` is ignored (`unsupported-property`). |
| Custom properties and `var()` | supported | Fallbacks, nesting, cycles (invalid, so the fallback applies); a `var()` that cannot be resolved makes its property `unset`. Substitution is limited by `MaxVarBytes`: past it the property is dropped with `var-budget`. |
| Rules for `::before` and `::after` | supported | The style stage computes the pseudo-element style (inherited from its element); a pseudo-element without `content`, or with `none` or `normal`, generates no box. |
| Comments, escapes (`\41`, `\A`), `!important` | supported | Escapes are decoded in identifiers, strings and URLs. |
| Error recovery (CSS Syntax §5) | supported | A malformed rule or declaration is dropped alone, the rest of the sheet is kept; each dropped item is reported as `invalid-value`. A `}` ends an unfinished item inside a block. |
| `@media` | supported | Nested `@media` rules, up to 64 levels. |
| `@page` and its 16 margin at-rules | supported | All 16 margin boxes are parsed; corner and side boxes are ignored with `unsupported-at-rule` when the sheet is loaded. |
| `@charset` | ignored | Only accepted at the very start; the text is always UTF-8. |
| `@import`, `@font-face`, `@supports`, `@keyframes` and any other at-rule | ignored | Skipped with its block, reported as `unsupported-at-rule`. Nothing is ever loaded. |
| Selectors: type, `*`, `#id`, `.class`, `[attr]`, `[attr=value]` and `~= \|= ^= $= *=` with `i`/`s` | supported | Names are matched in lowercase (HTML); no namespaces (`ns\|tag` is dropped). |
| Combinators: descendant, `>`, `+`, `~` | supported | A selector has at most 32 compound selectors of at most 32 simple selectors each. |
| `:root`, `:first-child`, `:last-child`, `:nth-child(an+b\|odd\|even)` | supported | |
| `:hover`, `:focus`, `:active`, `:visited`, `:focus-within`, `:focus-visible`, `:target` | supported | Parsed, never match on paper. |
| `::before`, `::after` (also `:before`, `:after`) | supported | Matched on the originating element; the style stage applies them to the generated box. |
| Other pseudo-classes and pseudo-elements (`:not()`, `:is()`, `:first-of-type`, `::first-line`...) | ignored | The whole selector list is dropped with `unsupported-selector`, as CSS requires for an invalid selector. |
| Specificity and the 5 000 selector budget | supported | Every member of a list counts; beyond 5 000 the render fails with `LimitSelectors`. |
| Media queries: `all`, `print`, `screen`, `not`, `only`, `and`, `,` with `width`, `height` (also `min-`/`max-`) and `orientation` | approximated | The medium is always print, with the page area as viewport. Any other feature, a range (`width >= 600px`) or a malformed query evaluates to false and is reported as `invalid-value`; an unknown media type is valid and simply does not match. |
| Nesting of blocks, functions and parentheses | approximated | Limited to 64 levels in one selector or value; a deeper item is dropped with `invalid-value`. |
| Control characters and invalid UTF-8 in CSS text | approximated | Replaced by U+FFFD. |

## Values and units

| Feature | Status | Notes |
|---|---|---|
| Lengths: `px`, `pt`, `pc`, `in`, `cm`, `mm`, `Q`, `em`, `rem`, `%`, unitless `0` | supported | Absolute units are converted to px; values are clamped to ±1e7 px. |
| Other units (`ex`, `ch`, `vw`, `vh`, `vmin`, `vmax`) and `calc()` | ignored | Declaration dropped with `invalid-value`. |
| Colors: `#rgb`, `#rgba`, `#rrggbb`, `#rrggbbaa`, `rgb()`, `rgba()`, named colors, `transparent` | supported | Both the comma and the space/slash syntaxes of `rgb()`; components are clamped. |
| `currentcolor` | supported | In `color` (inherits), `background-color` and the border colors. |
| `hsl()`, `hwb()`, `lab()`, `color()`, system colors | ignored | Declaration dropped with `invalid-value`. |
| `linear-gradient()`, `radial-gradient()` | approximated | A radial gradient is `[circle \| ellipse] [farthest-corner] [at center]` only (other sizes and positions are `invalid-value`). Angle (`deg`, `rad`, `grad`, `turn`) or `to <side|corner>`, 2 to 64 color stops with optional percentages; no hints, no lengths as positions. `repeating-` and other gradient types are ignored. |
| Functions with many arguments | approximated | At most 128 arguments or stops are examined; a function with more is rejected. |

## Layout

| Feature | Status | Notes |
|---|---|---|
| `display`: `none`, `block`, `inline`, `list-item`, `table` and the table-* values | supported | `list-item` is a block: markers are not drawn. `inline-block`, `flex` and `grid` are supported (see their rows); `inline-flex` and `inline-grid` are dropped with `invalid-value`. |
| `box-sizing`, `margin`, `padding` (with `auto`, `%`, 1 to 4 values), `width`, `max-width` | supported | Negative padding and width are invalid. `height` (length or percentage; a percentage of an auto height is auto; a block is sliced across pages and its fragments sum to the height; content taller than it is clipped with `overflow: hidden`, else it overflows and goes on on the next pages, the next sibling following the overflow when it crosses a page, where Chrome overlaps it) and `min-width` (CSS 2.1 §10.4) are supported; `min-height`, `max-height`: `unsupported-property`. |
| `border`, `border-<side>`, `border-width/style/color`: `none`, `hidden`, `solid`, `dashed`, `dotted`; `thin`, `medium`, `thick` | supported | The width is 0 while the style is none or hidden. A dashed or dotted side is one stroke along the whole side, corners included, with Chrome's pattern: dashes of 3 widths and gaps of 2 (2 and 1 from 3 px), dots as wide as the border (round from 4 px), the gap adjusted so that a dash or dot ends each side; a side too short for two dashes is solid, one that would take over 65 536 dashes is solid. Around rounded corners a border of one width, color and style is one closed stroke along its middle; mixed sides there are drawn solid. A collapsed table edge is drawn whole by the cell before it. Deviations from Chrome: a dotted side of a box 7 px wide or less (shorter than a few dots) is drawn as the others, not as Chrome's corner pieces and shifted run; dashes are stroked on the visible part of the page only. A negative width drops the whole `border` shorthand (`invalid-value`). |
| Border width snapping | supported | As in Chrome, each side width is snapped when computed: 1 px or more is floored to whole px (2.5pt = 3 px), under 1 px becomes 1 px, 0 stays 0; thin, medium and thick are 1, 3 and 5 px. The snapping comes before the page `scale`, in margin boxes too. In a collapsed table the snapped width is split half and half between the cells. |
| `border-radius` (1 to 4 values, `/`, `%`) and the four corner longhands | supported | |
| `background`, `background-color`, `background-image` | approximated | A color and/or a `linear-gradient()`; positions, sizes and repeats are not supported. |
| `overflow` | approximated | `hidden` and `clip` clip; `auto`, `scroll` and `visible` do not. |
| `border-collapse`, `border-spacing`, `table-layout` | supported | `table-layout: fixed`: column widths come from the cells of the first row and the `col` elements. `table-layout: auto` (the default): the minimum and maximum width of each column come from its cells (widths in px and %, `colspan` and `min-width` included), the table is as wide as its width or its content asks (shrink-to-fit) and the excess is shared as Chrome does; a table can be wider than its container when its columns cannot shrink. A `height` on a table, row or cell is a minimum that stretches the rows. Collapsed borders: the wider wins, the left or top cell on a tie, `hidden` removes the edge; row and group borders are ignored. Separated model: each cell draws its own borders, `border-spacing` applies. |
| Block layout: margin collapsing (siblings, parent and first or last child, empty boxes), auto margins, `%` of the containing block, `box-sizing` | supported | The root element and boxes with `overflow: hidden` keep the margins of their children inside. |
| Fragmentation (`break-before`, `break-after`, `break-inside`) | approximated | Pages break between blocks and between lines. `page`, `left`, `right`, `recto` and `verso` force a break between siblings (not before the first child of a page; the margins after it are kept); `avoid` and `avoid-page` are a preference between siblings and inside a block, and give way when they cannot be met (a box taller than a page is split where it is). `break-inside: avoid` on a table row moves the row whole. Forced breaks inside a table cell, an inline-block or a flex or grid item are ignored. There is no orphans/widows control, and no propagation of a break from the first or last child to its parent. Margins next to an unforced break are truncated. A border or padding that does not fit a page is sliced over the following pages. |
| Negative margins across a page break | approximated | A negative margin moves a box up within its page. A box that it would pull above the top of the page area goes at the top of the current page instead, for every amount, and so do flex and grid items pulled above their line. Chrome draws such a box on an earlier page when the pull is shorter than the pages it crosses (a margin of −50 px after a break: Chrome draws it at the bottom of the previous page; −250 px: on the page 250 px back), and nowhere when it is above the document (−1000 px); the layout goes page by page and never returns to a finished page, and no text is dropped. The boxes may overlap what is already at the top of the page. |
| Author lengths that place text outside the page: `line-height` or `vertical-align` beyond the page, negative `margin-left`, `text-indent` | approximated | The text is laid out and emitted at the position the lengths give and the page clips it, as in Chrome (which also splits a line taller than the page over several pages; this engine draws it once). Text moved sideways off the page is not checked by the kept-text tests. Hostile document data cannot set CSS, so these are author choices, not data. A single line box taller than about 4e7 px minus its position can lose that line inside a cell, flex item or inline-block (for example an inline-block with 1e7 px of padding, border and height and a `vertical-align` of −1e7 px). |
| `Options.Scale` | supported | The page area is laid out at 1/Scale of its size and drawn at Scale; margin boxes are not scaled. |
| `box-shadow` (outer, up to 8) | approximated | Drawn under the box, before its background: spread and offset applied to the border box; a blur is 4 concentric translucent rounded rectangles over the blur radius (no smooth falloff), not clipped to the outside of the box. At most 4096 shadow rectangles per page, the rest of the page gets none (`clamped`, `box-shadow items per page`). `inset` shadows are dropped with `unsupported-property` (`box-shadow inset`); more than 8 are cut with `clamped`. Non-atomic inline boxes get none. |
| `opacity` | approximated | The alpha of the text, background and border colours is multiplied by the opacity of the element and its ancestors; there is no transparency group, so overlapping descendants are each translucent on their own. The opacity is also folded into the stop alphas of a gradient background (used value). |
| `columns`, `column-count`, `column-gap`, `column-rule` on a block (multi-column) | approximated | Content flows over `column-count` columns of equal width, as over pages: breaks, `break-inside: avoid`, cut table rows and repeated `thead` work per column. The last segment is balanced (Chrome's height: the content as one column divided by the count, raised to the smallest height that fits; at most 20 layout passes). `column-gap: normal` is 1em. The rule is drawn between non-empty columns (solid only until M4-06). The count is clamped so that every column is at least 1 px wide (`clamped`, `columns`). Orphans and widows of 2 apply inside columns only. A multi-column box inside another is laid out as one column (warned: `unsupported-property`, "nested columns"). Also works on a table cell, a flex item and an inline-block. |
| `column-width`, `column-span`, `column-fill`, `break-before: column`, `break-after: column`, `min-height` | unsupported | Warned (`invalid-value` or `unsupported-property`) and ignored. Known differences from Chrome: with a `height`, Chrome adds columns past the count where we continue on the next page (and, in a cell, flex item or inline-block, the last column runs on downwards); a container wider than the page area is not narrowed; a two-line paragraph is split over 3 balanced columns by Chrome only; a balanced table row cut can leave a 1 px sliver of padding in the next column. |
| `display: flex`, `flex-direction: row`, `flex-wrap`, `justify-content`, `align-items`, `flex`, `flex-grow`, `flex-shrink`, `flex-basis`, `row-gap`, `column-gap`, `gap` on a flex container | approximated | Row direction only; items are laid out by the CSS Flexbox §9.7 algorithm (grow and shrink, `wrap` lines). A flex line is monolithic: it is never split between pages unless it is taller than a page. `margin: auto` and baseline alignment are not supported before M3-06. |
| `display: grid`, `grid-template-columns` (px, %, `fr`, `auto`, `min-content`, `max-content`, `repeat(n, …)`, at most 1000 tracks), `column-gap`, `row-gap`, `gap`, `align-items` on a grid | approximated | Items are placed one per cell in row-major order (no `grid-column`/`grid-row`, spans or `grid-template-areas`); rows are implicit and as tall as their tallest item; items fill their column (`justify-items: stretch`). A row is never split between pages unless it is taller than a page. Track sizing follows CSS Grid §12 for single-cell items. A grid inside an inline-block or a flex item sized by its content is sized like a block (by its widest item), not by its tracks (approximation, M3-06); lists beyond 1000 tracks are cut with `clamped`. |
| `display: inline-block` | approximated | Sized by its content (shrink-to-fit) or its `width`; it sits on the line like an atom. A line box is never split: a line holding an inline-block taller than a page moves to the next page, leaves the rest of the page blank, then is sliced there (as Chrome). |
| `text-transform`: `none`, `uppercase`, `lowercase` | approximated | Simple case mapping, character by character (no locale rules, no `capitalize`, no `full-width`). |
| `font-variant-numeric`: `normal`, `tabular-nums` | accepted | Parsed and inherited; no effect, the reference fonts already have tabular figures. |
| `string-set` and running strings | unsupported | Not implemented, like Chrome: there is no running header or footer from the content. |
| `position`: `static`, `relative`, `absolute`, `fixed`; `top`, `right`, `bottom`, `left`; `z-index` | approximated | `sticky` is `invalid-value`. A `fixed` box has the page area as containing block and is on every page from the first, in the z-order of the absolute boxes (above them at equal rank), clipped by the page only; with no `top` and `bottom` it starts on the page of its static position, at its static y, and repeats on the following pages. Deviations from Chrome: a fixed box taller than the page is not continued on the next page; the absolute ancestor of a fixed box stays on its static page; percentage widths of a fixed box are about 0.9 px wider than Chrome's. Past 4096 display items per page the remaining fixed boxes are drawn on their first page only (`clamped`: `fixed boxes`). An absolute box is blockified; a `relative` box is a containing block and is shifted at drawing time by `left` (else `-right`) and `top` (else `-bottom`), percentages of its containing block; the flow and its siblings do not move. |
| `transform: none \| rotate(<angle>)` | approximated | Other functions are `invalid-value`; `transform-origin` is `unsupported-property` (the origin is the border box centre). |
| `float` | ignored | `unsupported-property`. |
| `counter-reset`, `counter-increment`, `content` of `::before` and `::after` | approximated | At most 32 counters per list (`clamped`), 64 content items (`clamped`); `content` takes strings and `counter(name[, decimal \| decimal-leading-zero])` only: `attr()`, `counters()`, `leader()`, `target-counter()`, `target-text()` and other counter styles make the declaration `invalid-value`. A name listed twice in `counter-reset` keeps the last value, in `counter-increment` the sum. |
| `leader()`, `target-counter()`, `target-text()`, `attr()` in `content` | unsupported | The whole `content` declaration is `invalid-value`, as in Chrome: the table of contents of 02 has no leader dots or page numbers. |
| `page` and `@page <name>` | supported | A named page rule applies on top of the unnamed ones; other page selectors stay unsupported. |

## Text and fonts

| Feature | Status | Notes |
|---|---|---|
| `font-family` (names, strings, generic families), `font-size` (lengths, `%`, keywords, `smaller`, `larger`), `font-weight` (1 to 1000, `bold`, `bolder`, `lighter`), `font-style`, `line-height`, `color`, `letter-spacing`, `text-align`, `vertical-align` (`baseline`, `top`, `middle`, `bottom`, a length) | supported | At most 32 font families are kept; font sizes are clamped to 10 000 px. `text-align: justify` is dropped with `invalid-value`. `font` (shorthand): unsupported in M1 (`unsupported-property`): the declaration is dropped, so `font-family`, `font-size`, `font-weight` and `line-height` fall back to their inherited or initial values; supported from M2. |
| `vertical-align: <length>` (px, em, mm... positive raises, negative lowers) | supported | On inline boxes and atomic inlines (inline-blocks, svg), cumulative over enclosing inline boxes, relative to the parent baseline; the line grows to hold the shifted box. A percentage, `sub`, `super`, `text-top` and `text-bottom` are `invalid-value`. |
| `white-space`: `normal`, `pre`; `overflow-wrap` and `word-wrap`: `normal`, `break-word`, `anywhere`; `word-break`: `normal`, `break-all` | supported | `anywhere` places like `break-word`; `break-all` adds a break opportunity between letters, digits and the symbols Chrome treats like them (`_`, `#`, `@`...), after `. , : ; / -` and around `(` and `)`; never inside a grapheme (marks, joiners, Hangul jamo, Indic conjuncts), not under `white-space: pre`, and not between two adjacent inline boxes (`a<b>b</b>`). Their min-content effect (one grapheme) is not implemented: M1 has no min-content consumer (fixed table layout), it comes with auto table layout in M3. `nowrap`, `pre-wrap`, `pre-line` and the other `word-break` values are dropped with `invalid-value` until M2. |
| `text-decoration` (`underline`, `line-through`, `none`) | supported | Not inherited; the box stage propagates it. `overline` is dropped with `invalid-value`. `text-decoration-thickness`: `auto` and `from-font` keep the font's thickness; a length or a percentage of the font size is rounded to whole px, at least 1, as Chrome does, and is the one of the box that declares the decoration (its children inherit it, a block's decoration does not pass it to the blocks inside). |
| `list-style`, `list-style-type` | approximated | Only `none` is kept; markers are never drawn. |
| UA sheet | supported | Chrome's values for the HTML subset (headings, lists, tables, `a[href]` blue and underlined, `pre`, `code`...). `img`, `object`, `iframe`, `video`, `canvas`, `input`... are `display: none` with `unsupported-element`. |
| Mark positioning (GPOS offsets) | Not supported (M1-M4) | Shaped glyphs keep their advance but not their X/Y offsets, so combining marks are not repositioned: precomposed characters render correctly, stacked or detached marks may overlap their base. |

## Paged media

| Feature | Status | Notes |
|---|---|---|
| `@page` `size`: `auto`, named sizes (`A3`, `A4`, `A5`, `B4`, `B5`, `letter`, `legal`, `ledger`), `landscape`, `portrait`, one or two lengths | supported | Each side is clamped to 1 in to 200 in (`clamped`). |
| `@page` margins: `margin` and `margin-*` | supported | Margins that leave less than 1 in of page area are scaled down together (`clamped`). Other descriptors: `unsupported-property`. |
| `@page` selectors (`:first`, `:left`) | ignored | The rule is dropped with `unsupported-at-rule`. A page name (`@page cover`) is supported. |
| Margin boxes `@top-left|center|right`, `@bottom-left|center|right` | supported | Font, color, background, padding, `text-align`, `vertical-align`, `content`. Their text is aligned and vertically centered by default. |
| Margin text containing `counter()` | approximation | The text is not wrapped: it stays on one line, clipped to its box, starting at the box start when it overflows. A text without counter wraps in its box. No warning. |
| `content` of a margin box: strings, `counter(page)`, `counter(pages)`, `none`, `normal` | supported | Strings go through the text sanitation of design section 8.4. |

## HTML elements and attributes

| Feature | Status | Notes |
|---|---|---|
| `<a href>` | supported | Only `http`, `https` and `mailto` targets are drawn as links; the scheme is lowercased, spaces and non-ASCII are percent-encoded, a target over 2 KiB or with a control character inside is dropped. Any other scheme, a relative target and `javascript:` are reported as `blocked-link`. A `#id` link to an element that exists is an internal link to a named destination placed at the top of that element, written like Chrome (y = page height less the offset in the page area, unscaled); a link to a missing or `display: none` id makes no annotation. At most 20 000 links (`clamped`, `links`) and 10 000 destinations (`clamped`, `destinations`) per document. |
| `<br>`, white space | supported | Collapsible white space collapses across inline boxes and is dropped at the start and end of a line; `white-space: pre` keeps spaces and turns newlines into line breaks. In preserved text a tab moves to the next multiple of 8 characters (counted in characters, not in widths). |
| Block elements inside inline elements | supported | The inline box is split around the block, as in CSS 2.1 §9.2.1.1; loose inline content next to blocks gets an anonymous block. |
| `<svg>` | approximated | Inline svg is drawn as paths: `path`, `rect`, `circle`, `ellipse`, `line`, `polyline`, `polygon`, `g`, with `viewBox`, `fill`, `stroke` and their presentation attributes; text, `use`, `defs`, gradients, transforms and CSS inside the svg are ignored (`unsupported-element`). At most 10 000 shapes (`clamped`) and 64 KiB per `d` attribute. |
| `<math>` | ignored | The subtree is skipped and reported as `unsupported-element`. |
| `<table>` and its parts | approximated | Missing rows, groups and cells are added as anonymous boxes; `colspan` is clamped to [1, 1000] (`clamped`), the content of cells past column 1000 is moved, in order, to the end of the last cell of the row (`clamped`; the moved cell's own background, border, alignment and `white-space` do not apply, its id does) and a colspan that reaches past it is shortened (`clamped`), `rowspan` is rendered as 1 (`clamped`). A row that does not fit breaks between the line boxes of its cells (all cells continue on the next page); a cut row runs to the bottom of the page and leaves at least two lines on the next one; a `break-inside: avoid` row taller than a page moves to the next page first, then is cut; a row of single lines moves whole; a row taller than an empty page is sliced, each line staying in the slice that holds its baseline (`clamped`, only for the sliced case). The first `thead` repeats on each continuation page. `caption` is drawn above the table; `tfoot` comes after the body and is not repeated. `vertical-align` on cells: top, middle, bottom, baseline. |
| `col` and `colgroup` widths | supported | Fixed layout: the width (px, mm or %) of a `col` wins over the width of the first-row cells; `span` is honoured (clamped to 1,000). A column no cell uses still takes its width. |

## Limits worth knowing

| Limit | Notes |
|---|---|
| Content of one page | 16 MiB of drawing operators per page. A single line whose drawing operators exceed 16 MiB fails with `LimitOutputBytes` (about 1.2 M glyphs with letter-spacing; plain text up to `MaxGlyphs` fits). |
| Gradients | At most 64 stops per gradient and 4,096 distinct gradients per document; further ones are drawn as a solid color (`clamped`). Translucent stops and `radial-gradient()` are drawn (a luminosity soft mask carries the alpha); a translucent gradient costs two of the 4,096 shadings. |
